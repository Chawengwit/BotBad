# 1. ที่มาและขอบเขต

ผู้ใช้ขอ (2026-09-19) หลังเหตุการณ์ถอนชื่อ louis:

> ถ้ามีหลายเกมเปิดอยู่ และ user ที่จะถอนชื่อออก อยู่หลายเกม ให้ถามกลับว่าจะเอาจากเกมไหน

แต่ตอนนี้ 1 กลุ่มเปิดรอบได้ครั้งละ 1 รอบ (spec §7) และ Database บังคับไว้ด้วย unique index
สถานการณ์นี้จึงยังเกิดขึ้นไม่ได้ ต้องเปลี่ยนกติกาก่อน

ปัญหาเดิมที่แก้ไปพร้อมกัน:

- ก๊วนที่ตีหลายวันต่อสัปดาห์ต้องปิดรอบแรกก่อน ถึงจะเปิดรอบถัดไปได้
- รอบที่คนเปิดลืมปิดขวางทั้งกลุ่มไม่ให้เปิดรอบใหม่ (ความเสี่ยงที่ spec §7 ยอมรับไว้ตอน MVP)

# 2. สิ่งที่ตัดสินใจแล้ว (ถามผู้ใช้ 2026-09-19)

| เรื่อง | ตัดสินใจ |
| --- | --- |
| จำนวนรอบที่เปิดพร้อมกัน | **สูงสุด 3 รอบต่อกลุ่ม** |
| คำสั่งไม่ได้บอกว่ารอบไหน | ดูเฉพาะรอบที่คำสั่งนั้นทำได้ เหลือรอบเดียวทำเลย หลายรอบขึ้นปุ่มให้เลือก (ใช้กับ `ลงชื่อ` ด้วย) |

| วิธีเริ่ม | เขียน PRP นี้ให้อนุมัติก่อนเขียนโค้ด |
| พิมพ์วันต่อท้ายคำสั่ง (`ลงชื่อ พุธ`) | ไม่รับ เลือกด้วยปุ่มหรือพิมพ์เป็นประโยค (รีวิวรอบ 1) |
| ถอนคนอื่นผ่านประโยคตอนเขาอยู่หลายรอบ | กดเลือกรอบแล้วถอนเลย นับเป็นการยืนยัน (รีวิวรอบ 1) |
| คิดเงินกับการปิดรอบ | **แยกกัน** เปิดเกม → ปิดเกม แล้วค่อย เปิดบิล → ปิดบิล ตอนเปิดบิลเลือกได้ว่าบิลใหม่ หรือบิลจากเกมที่เพิ่งปิด (รีวิวรอบ 1, §5.1) |
| เกมที่เปิดบิลได้ | เกมที่ยังเปิดอยู่ + เกมที่ปิดไปไม่เกิน 7 วัน (รีวิวรอบ 1) |
| ปิดบิล | บิลที่ทุกคนจ่ายครบ หรือยกเลิกแล้ว ไม่มีคำสั่งใหม่ (รีวิวรอบ 1, ตรงกับที่ตัดสินไว้ 2026-09-18) |

# 3. Scope

## 3.1 ทำ

- เปิดรอบได้สูงสุด 3 รอบพร้อมกัน
- ทุกคำสั่งเรื่องรอบเลือกรอบเองเมื่อชัด ถามด้วยปุ่มเมื่อไม่ชัด
- ปิดรอบที่เลยวันเล่นแล้วอัตโนมัติทุกเช้า
- LLM เลือกรอบจากวันที่ผู้ใช้พูดถึงได้
- สรุปวันศุกร์ขึ้นทุกรอบที่เปิดอยู่

## 3.2 ไม่ทำ พร้อมเหตุผล

| ตัดออก | เหตุผล |
| --- | --- |
| พิมพ์วันต่อท้ายคำสั่ง เช่น `ลงชื่อ พุธ` | ชนกับการลงชื่อแทน `ลงชื่อ กิ้ฟ` ถ้ามีแขกชื่อ "พุธ" จะกำกวม ใช้ปุ่ม หรือพิมพ์เป็นประโยคให้ LLM อ่านแทน |
| push แจ้งตอนปิดรอบอัตโนมัติ | กินโควตา push (PRP guests-split-bills-and-digest §2.2) สรุปวันศุกร์บอกบิลค้างอยู่แล้ว |
| กันรอบวันเวลาซ้ำกัน | เปิดรอบต้องกดยืนยันอยู่แล้ว และบางก๊วนจองสองสนามเวลาเดียวกันจริง |
| ให้ใครก็ปิดรอบของคนอื่นได้ | ยังไม่มีใครขอ ปิดอัตโนมัติแก้ปัญหารอบค้างแทนแล้ว |

# 4. เลือกรอบ

## 4.1 หลักการ

ไม่ระบุรอบ → ดูเฉพาะรอบที่คำสั่งนั้นทำได้จริง (หลักเดียวกับการเลือกบิล PRP guests-split-bills-and-digest §5.2)

```text
ไม่เหลือรอบไหนเลย → บอกเหตุผล
เหลือ 1 รอบ       → ทำเลย ไม่ถาม
หลายรอบ           → การ์ด "รอบไหน?" ปุ่มละรอบ เรียงตามวันเล่น
```

กลุ่มที่มีรอบเดียว **ทุกคำสั่งเลือกรอบเหมือนเดิม** ไม่มีคำถามเพิ่ม
ที่เปลี่ยนสำหรับทุกกลุ่มมีแค่การปิดอัตโนมัติ (§5) และเปิดบิลจากเกมที่เพิ่งปิดได้ (§5.1)

## 4.2 ตารางคำสั่ง

| คำสั่ง | รอบที่เลือกได้ | ไม่เหลือรอบไหนเลย |
| --- | --- | --- |
| `เปิดตี` | – เปิดรอบใหม่ เปิดครบ 3 รอบแล้วเปิดไม่ได้ เช็กตั้งแต่เริ่ม wizard และเช็กซ้ำตอนกดยืนยัน | `GAME_LIMIT_REACHED` |
| `ลงชื่อ` | รอบที่ยังไม่ได้ลง และยังไม่เต็ม (เหลือรอบเดียวลงเลย ผู้ใช้เลือกแล้วแม้อาจลงผิดวัน ผลลัพธ์บอกรอบเสมอ §4.4) | ลงครบทุกรอบแล้ว `ALREADY_JOINED` · ที่เหลือเต็มหมด `GAME_FULL` · ไม่มีรอบ `NO_OPEN_GAME` |
| `ลงชื่อ <ชื่อ ...>` | รอบที่ยังไม่เต็ม ทุกชื่อลงรอบเดียวกัน (กติกาเดียวกับ `ลงชื่อ`) | `GAME_FULL` · `NO_OPEN_GAME` |
| `ถอนชื่อ` | รอบที่คนพิมพ์ลงไว้ | `NOT_JOINED` |
| `ถอนชื่อ <ชื่อ ...>` | รอบที่มีคนในรายชื่อที่ถอนได้ | `ℹ️ <ชื่อ> ไม่ได้อยู่ในรายชื่อรอบไหนเลย` |
| `ใครตีบ้าง` / `รายชื่อ` | ทุกรอบ | แสดงทุกรอบเลย ไม่ถาม (ไม่เกิน 3 การ์ด ใส่ใน reply เดียวได้) |
| `แก้ไข` / `ยกเลิก` / `ปิดรอบ` | รอบที่คนพิมพ์เป็นคนเปิด | `NOT_GAME_CREATOR` · `NO_OPEN_GAME` |
| `คิดเงิน` → บิลจากเกม | เกมที่คนพิมพ์เป็นคนเปิด มีคนลงชื่อ และยังเปิดอยู่หรือปิดไปไม่เกิน 7 วัน (ไม่รวมเกมที่ยกเลิก) | ปุ่มบิลจากเกมไม่ขึ้น พร้อมเหตุผลใต้คำถาม (เหมือนเดิม) |

เคสที่ผู้ใช้ขอ: `บอทจ๋า ถอนชื่อ` ตอนลงไว้ทั้งรอบพุธและเสาร์ → ถามว่าถอนจากรอบไหน
ลงไว้รอบเดียว → ถอนเลย แม้กลุ่มจะเปิดอยู่ 3 รอบ

ข้อจำกัดที่ยอมรับ: คำสั่งเดียวทำกับรอบเดียว `ถอนชื่อ กิ้ฟ วิท` ตอนกิ้ฟอยู่พุธ วิทอยู่เสาร์
→ ถามว่ารอบไหน กดพุธได้แค่กิ้ฟ วิทขึ้นว่าไม่อยู่ในรายชื่อรอบนี้ ต้องสั่งอีกครั้งสำหรับรอบเสาร์

## 4.3 การ์ด "รอบไหน?"

```text
📅 ถอนจากรอบไหน?
[พุธ 24 ก.ย. 19:00 · คอร์ทสามย่าน]
[เสาร์ 27 ก.ย. 18:00 · ABC Badminton]
[ยกเลิก]
```

- ผูกกับ pending action ชนิดใหม่ `choose_game` เก็บคำสั่งกับรายชื่อที่พิมพ์มาไว้ใน payload
  กดได้เฉพาะคนสั่ง กดได้ครั้งเดียว หมดอายุ 10 นาที (spec §21 เดิม)
- กดแล้วเช็กใหม่ทั้งหมดตอนทำจริง ระหว่างรอกดรอบอาจเต็ม ถูกปิด หรือคนถูกถอนไปแล้ว
- ป้ายปุ่มไม่เกิน 40 ตัวอักษร (ข้อจำกัดของ LINE) ปุ่มละแถว ชื่อคอร์ทยาวเกินตัดท้ายด้วย `…` (ใช้ `fitLabel` เดิม)
- พิมพ์ตอบแทนการกดได้ในโหมดฟัง เช่นพิมพ์ "เสาร์" → LLM อ่านต่อได้ เพราะข้อความของการ์ดถูกจำไว้ใน session แล้ว (llm-design §8)
- ถอนคนอื่นผ่านประโยค: **กดเลือกรอบแล้วถอนเลย** นับเป็นการยืนยันไปในตัว ไม่ต้องกดสองชั้น
  ถ้าเหลือรอบเดียวยังขึ้นการ์ดยืนยันการถอนตามเดิม (`leave_players`)

## 4.4 ผลลัพธ์ต้องบอกว่ารอบไหน

กลุ่มที่เปิดหลายรอบ ข้อความผลลัพธ์ต้องบอกรอบด้วย ไม่งั้นทั้งกลุ่มไม่รู้ว่าลงหรือถอนรอบไหน

```text
✅ เชวง ลงชื่อแล้ว (พุธ 24 ก.ย. 19:00)
👥 5/8 คน
```

ใส่เวลาเริ่มด้วย เพราะวันเดียวกันเปิดได้หลายรอบ (§3.2 ไม่กันรอบวันเวลาซ้ำ) ตัดสินตอนเขียนโค้ด §15

กลุ่มที่มีรอบเดียว ข้อความเหมือนเดิม

## 4.5 ปุ่มเก่าที่ค้างในแชท

postback `join` / `leave` / `list` เดิมไม่มี game id ให้ทำเหมือนพิมพ์คำสั่ง
คือเลือกรอบตาม §4.2 และถามด้วยการ์ดเมื่อมีหลายรอบ

# 5. ปิดรอบอัตโนมัติ

- cron เดิม `/api/cron/daily` (10:00 เวลาไทย ทุกวัน) เพิ่มงานปิดรอบที่ `play_date < วันนี้` ตามเวลาไทย → `status = 'completed'`
- รอบที่เล่นคืนนี้จะปิดพรุ่งนี้ 10 โมง ระหว่างนั้นยังลงชื่อ ถอนชื่อได้เหมือนเดิม
  ที่ไม่ปิดทันทีที่เลิกเล่น เพราะ cron บน Vercel Hobby ยิงได้วันละครั้ง (PRP guests-split-bills-and-digest §2.3)
- ไม่ push แจ้ง บิลของรอบยังตามเก็บเงินต่อได้ (bill-splitting §5.4) สรุปวันศุกร์ยังบอกบิลค้าง
- ปิดรอบด้วยมือยังทำได้เหมือนเดิม และยังเตือนคนค้างจ่ายตอนปิด
- ตัดหัวข้อ "รอบค้างเก่า" ออกจากสรุปวันศุกร์ เพราะรอบพวกนั้นถูกปิดไปก่อนถึงวันศุกร์เสมอ
- การ์ดที่ค้างในแชทของรอบที่ถูกปิดไปแล้ว (แก้ไข ยกเลิก ปิด เลือกรอบ ถอนชื่อ) กดแล้วไม่มีผล
  เพราะตอนกดล็อกรอบด้วย `game_id` ของการ์ดและเช็กว่ายังเปิดอยู่ (หลักเดิมของ spec §21)

## 5.1 คิดเงินแยกจากการปิดรอบ (ผู้ใช้ตัดสิน รีวิวรอบ 1)

รีวิวรอบ 1 พบว่าปิดอัตโนมัติชนกับกติกาเดิมที่คิดค่ารอบได้เฉพาะรอบที่ยังเปิดอยู่
(`requireBillableGame` และ bill-splitting ข้อตัดสินใจ 6 "คิดเงินก่อนปิดรอบเสมอ")

ผู้ใช้ตัดสินให้แยกสองเรื่องออกจากกัน:

```text
เกม:  เปิดเกม → ปิดเกม (เองหรืออัตโนมัติ)
บิล:  เปิดบิล → ปิดบิล
      ตอนเปิดบิลเลือกได้ว่า บิลใหม่ หรือ บิลจากเกมที่เพิ่งปิด (รายชื่อคนดึงจากเกมนั้น)
```

- ปิดเกมได้เลยโดยไม่ต้องรอคิดเงิน การปิดไม่ขวางการคิดเงินอีกต่อไป
- **เกมที่เปิดบิลได้:** เกมที่ยังเปิดอยู่ + เกมที่ปิดไปไม่เกิน 7 วัน ไม่รวมเกมที่ยกเลิก (ไม่ได้เล่น)
  เวลาที่ปิดอ่านจาก `games.updated_at` ซึ่ง `updateGameStatus` ตั้งตอนปิด และเกมที่ปิดแล้วแก้ไขไม่ได้อีก
  จึงไม่ต้องเพิ่มคอลัมน์ `closed_at` (ปิดอัตโนมัติก็ต้องตั้ง `updated_at` เหมือนกัน)
- เปลี่ยน bill-splitting ข้อตัดสินใจ 6 เป็น "คิดค่ารอบได้ทั้งเกมที่เปิดอยู่และที่ปิดไปไม่เกิน 7 วัน"
- **ปิดบิล** = ทุกคนจ่ายครบ หรือคนสร้างยกเลิก ไม่มีคำสั่งใหม่ (นิยามเดียวกับที่ผู้ใช้ตัดสิน 2026-09-18)

⚠️ ผลต่อข้อมูลจริงตอน deploy: รอบที่ 6 ของกลุ่ม (18 ก.ย. 18:00 ยังไม่มีใครลงชื่อ) จะถูกปิดในเช้าวันแรกที่ cron ทำงาน

# 6. LLM

- system prompt: เปลี่ยน "รอบที่เปิดอยู่" เป็นรายการรอบ (ไม่เกิน 3) พร้อมบอกว่าคนที่คุยด้วยลงรอบไหนและเปิดรอบไหน
- เปลี่ยนกฎ "1 กลุ่มมีรอบที่เปิดอยู่ได้ครั้งละ 1 รอบ" เป็น "เปิดได้สูงสุด 3 รอบ"
- tool ที่ทำกับรอบรับ `round_date` และ `round_time` (ไม่บังคับ) ใส่เมื่อผู้ใช้พูดถึงวันหรือเวลา เช่น "ลงชื่อรอบวันเสาร์"
  ไม่ใช้ชื่อ `play_date` / `start_time` ตามร่างแรก เพราะ `propose_edit_game` ใช้ชื่อนั้นเป็นค่าใหม่ของรอบอยู่แล้ว (§15)
  `join_game` `leave_game` `list_players` `propose_edit_game` `propose_cancel_game` `propose_close_game`
  `start_bill` (kind game) และ `propose_create_bill` (บิลค่ารอบ)
- ไม่ระบุ หรือระบุแล้วยังกำกวม (สองรอบวันเดียวกัน) → ระบบขึ้นการ์ด "รอบไหน?" เอง
  เป็นข้อความของระบบ (llm-design §8) LLM ไม่ต้องถามเอง
- rules ใน prompt ที่อ้างชื่อ `get_open_game` ต้องแก้ตามชื่อใหม่ด้วย
- `get_open_game` เปลี่ยนเป็น `get_open_games` คืนทุกรอบที่เปิดอยู่

# 7. Database — migration 017

```sql
-- เลิกบังคับ 1 กลุ่ม 1 รอบ จำนวนสูงสุด 3 รอบบังคับในโค้ด
DROP INDEX uq_games_one_open_per_group;

-- การ์ด "รอบไหน?" ใช้ pending_actions ตัวเดิม
ALTER TABLE pending_actions DROP CONSTRAINT pending_actions_action_type_check;
ALTER TABLE pending_actions ADD CONSTRAINT pending_actions_action_type_check
  CHECK (action_type IN (
    'create_game', 'edit_game', 'cancel_game', 'close_game',
    'create_bill', 'cancel_bill', 'edit_bill', 'leave_players', 'choose_game'
  ));
```

- `idx_games_group_status (line_group_id, status)` มีอยู่แล้ว ใช้หารอบที่เปิดของกลุ่มได้เลย
- ไม่มีการ UPDATE ข้อมูลเดิมใน migration
- **จำกัด 3 รอบในโค้ด:** ตอนกดยืนยันเปิดรอบ ล็อกกลุ่มด้วย `pg_advisory_xact_lock(hashtext(line_group_id))`
  แล้วค่อยนับรอบที่เปิดอยู่ กันสองคนกดยืนยันพร้อมกันตอนมี 2 รอบแล้วได้ 4 รอบ
  (unique index ที่เคยกันเรื่องนี้ถูกลบไปแล้ว)

## ลำดับ deploy

1. รัน migration 017 กับ production
2. deploy โค้ดใหม่

ต้องรัน migration ก่อน เพราะโค้ดใหม่ใช้ pending action ชนิด `choose_game`
ช่วงรอ deploy โค้ดเดิมยังกันเปิดรอบที่ 2 ไว้ในแอปอยู่แล้ว เหลือแค่กรณีสองคนกดยืนยันเปิดรอบพร้อมกันพอดี

## ถอยกลับ (rollback)

พอมีกลุ่มเปิดหลายรอบแล้ว ถอยกลับไปโค้ดเดิมตรง ๆ ไม่ได้
โค้ดเดิมหยิบรอบที่เปิดอยู่แถวแรกแบบสุ่ม (query ไม่มี ORDER BY) และสร้าง unique index คืนจะล้มถ้ามีกลุ่มไหนเปิดเกิน 1 รอบ

ถ้าต้องถอย:

1. หากลุ่มที่เปิดเกิน 1 รอบ (`SELECT line_group_id FROM games WHERE status = 'open' GROUP BY 1 HAVING count(*) > 1`)
2. ให้คนเปิดรอบปิดหรือยกเลิกรอบที่เกิน หรือขออนุญาตผู้ใช้ปิดให้
3. deploy โค้ดเดิม แล้วค่อยสร้าง `uq_games_one_open_per_group` คืน

# 14. บันทึกรีวิว

**รอบ 1 (2026-09-19)** แก้ในเอกสารแล้ว:

- เช็กโควตา 3 รอบตั้งแต่เริ่ม wizard ไม่ใช่แค่ตอนกดยืนยัน (§4.2)
- ข้อจำกัดถอนหลายคนที่อยู่ต่างรอบในคำสั่งเดียว (§4.2)
- ป้ายปุ่มยาวเกิน และพิมพ์ตอบแทนการกดปุ่ม (§4.3)
- การ์ดค้างของรอบที่ถูกปิดอัตโนมัติ (§5)
- สองรอบวันเดียวกัน LLM ระบุแค่วันไม่พอ เพิ่ม `start_time` (§6)
- แผนถอยกลับ (§7)

พบปัญหาที่ต้องให้ผู้ใช้ตัดสิน ผู้ใช้ตอบแล้ว:

- `ลงชื่อ` เหลือตัวเลือกเดียวลงเลย (คงตามร่างเดิม)
- ไม่รับพิมพ์วันต่อท้ายคำสั่ง
- ถอนคนอื่นผ่านประโยค กดเลือกรอบแล้วถอนเลย
- คิดเงินแยกจากการปิดเกม (§5.1)
- เกมที่เปิดบิลได้: ยังเปิดอยู่ + ปิดไปไม่เกิน 7 วัน
- ปิดบิล = จ่ายครบหรือยกเลิก ไม่มีคำสั่งใหม่
