# 1. ทำไมต้องมีฟีเจอร์นี้

LINE ยอมให้มี Official Account ได้ **แค่ตัวเดียวต่อ 1 กลุ่ม** (ดู spec §22)

กลุ่มแบดจำนวนมากมีขุนทองอยู่แล้วเพื่อหารค่าสนาม แปลว่าผู้ใช้ต้อง**เลือกระหว่างขุนทองกับบอทจ๋า**
ถ้าบอทจ๋าหารเงินไม่ได้ ก๊วนที่ใช้ขุนทองอยู่จะไม่ย้ายมา

เป้าหมายไม่ใช่การทำ "ขุนทองอีกตัว" แต่คือ **ทำให้ก๊วนแบดไม่ต้องเลือก** โดยครอบคลุมเฉพาะเรื่องเงินที่เกิดในรอบตี

เราลอกไม่ได้ และไม่ควรลอก

# 3. Research: ก๊วนแบดคิดเงินกันยังไงจริง ๆ

จากกระทู้ Pantip ของคนจัดก๊วนจริง และโปรแกรมจัดก๊วนที่มีอยู่ (PlayMatch, BC COURT, badminton-match)
พบว่าวิธีคิดเงินมี 4 แบบหลัก

| แบบ | คิดยังไง | ใครใช้ |
| --- | --- | --- |
| **A. หารเท่าทั้งก้อน** | (ค่าคอร์ท + ค่าลูก + อื่น ๆ) ÷ จำนวนคน | ก๊วนทั่วไปที่มาพร้อมกันกลับพร้อมกัน |
| B. คิดตามชั่วโมงที่อยู่จริง | ค่าคอร์ทของแต่ละชั่วโมง ÷ คนที่อยู่ชั่วโมงนั้น | ก๊วนที่คนเข้าออกระหว่างรอบ |
| C. ค่าลูกตามคนที่ลงสนาม | นับลูกที่ใช้ต่อเกม แล้วหารเฉพาะ 4 คนในสนาม | ก๊วนซีเรียส/ซ้อมจริงจัง |
| D. ขาประจำ / ขาจร คนละราคา | ขาประจำเหมาจ่ายรายเดือน ขาจรจ่ายรายครั้ง | ก๊วนที่เช่าคอร์ทประจำรายเดือน |

## เลือกแบบ A อย่างเดียว

เหตุผลที่ตัด B, C, D ไม่ใช่ความขี้เกียจ แต่เพราะ **spec §8 Full-Time Rule เขียนไว้แล้วว่าทุกคนที่ลงชื่อเล่นเต็มรอบ**
ระบบเราไม่มีข้อมูล "ใครอยู่ชั่วโมงไหน" หรือ "ใครลงเกมไหน" ตั้งแต่ต้น

ถ้าจะทำแบบ B หรือ C ต้องรื้อ §8 ก่อน ซึ่งกระทบทั้งระบบ ส่วนแบบ D ต้องมีระบบสมาชิกและยอดยกมาข้ามเดือน

**ค่าลูกแบดหารเท่าทุกคน** — สอดคล้องกับ §8 และเป็นสิ่งที่ก๊วนส่วนใหญ่ทำอยู่แล้ว

## ค่าใช้จ่ายที่เจอจริงในก๊วน

```text
ค่าคอร์ท      → ยอดรวม พิมพ์ครั้งเดียว
ค่าลูกแบด     → จำนวนลูก × ราคาต่อลูก
ค่าน้ำ         → ยอดรวม
อื่น ๆ         → ค่าเช่าไม้, ค่าที่จอดรถ, ค่าโค้ช, ค่าขนม (ตั้งชื่อรายการเองได้)
```

# 4. Scope

## 4.1 ทำ (In Scope)

- 1 รอบตี = 1 บิล
- รายการค่าใช้จ่ายแยกรายการ: ค่าคอร์ท / ลูกแบด / ค่าน้ำ / อื่น ๆ (ตั้งชื่อเองได้)
- ลูกแบดคิดแบบ **จำนวน × ราคาต่อลูก**
- **หารเท่าทุกคนที่ลงชื่อรอบนั้น ทุกรายการ**
- **ตอนปิดรอบ บอทบอกให้รู้ว่าเหลือใครยังไม่จ่าย** แต่ไม่ขวางการปิดรอบ
- เลขพร้อมเพย์เก็บใน**ข้อมูลของรอบตี** ตั้งตอนเปิดรอบหรือแก้ทีหลังก็ได้ (เหมือนชื่อคอร์ท/แผนที่)
- ส่งบิลเข้ากลุ่มเป็นการ์ดสรุป
- คนที่อยู่ในบิลบอกเองว่าจ่ายแล้ว — พิมพ์ `บอทจ๋า จ่ายแล้ว` หรือกดปุ่ม `💸 จ่ายแล้ว`
- ดูได้ทุกเมื่อว่าใครจ่ายแล้ว / ใครยังค้าง

## 4.2 ไม่ทำ (Out of Scope) พร้อมเหตุผล

| ตัดออก | เหตุผล |
| --- | --- |
| ให้ผู้เก็บเงินกดยืนยันทีละคน | เพิ่มขั้นตอนโดยไม่ได้ความมั่นใจเพิ่ม เพราะบอทตรวจเงินเข้าไม่ได้อยู่ดี |
| ให้ผู้เก็บเงินกดแทนคนอื่น | คนจ่ายเงินสดก็อยู่ในกลุ่มและกดเองได้ กดผิดก็กด `ยังไม่จ่าย` เอง — ตัดปุ่มนี้ทิ้งได้ทั้งชุด |
| แก้/ลบรายการหลังส่งบิล | ยอดของทุกคนต้องคิดใหม่ทั้งที่บางคนจ่ายไปแล้ว → ให้ยกเลิกบิลแล้วคิดใหม่ (ใช้เวลา 20 วินาที) |
| แนบสลิปเข้าบิล | ตรวจของปลอมไม่ได้ (ดู §8) และรูปอยู่ในแชทกลุ่มให้เลื่อนดูได้อยู่แล้ว |
| ตรวจสลิปอัตโนมัติ | ไม่มีเจ้าไหนฟรี ถูกสุด 99 บาท/เดือน (ดู §8) |
| QR พร้อมเพย์ | ใช้เลขพร้อมเพย์เป็นข้อความพอ |
| OCR ใบเสร็จ | รอบตีไม่มีใบเสร็จให้สแกน พิมพ์ตัวเลข 3 ตัวเร็วกว่า |
| หารไม่เท่า / เลือกคนร่วมจ่ายต่อรายการ | ขัดกับ §8 Full-Time Rule → Phase 2 |
| คิดตามชั่วโมง / ตามคนลงสนาม / ขาประจำ-ขาจร | ต้องรื้อ §8 หรือทำระบบสมาชิก |
| ทวงอัตโนมัติทุกวัน | ต้องใช้ **Push API** กินโควตาฟรีของ LINE ขัด spec §27 |
| รับ-ส่งเงินจริง / ผูกบัญชีธนาคาร | เราไม่ใช่ผู้ให้บริการชำระเงิน มีเรื่องกำกับดูแลตามมา |
| ยอดค้างข้ามรอบ / แต้ม / leader board | ต้องมี ledger บานปลายทันที |

## 4.3 สิ่งที่ต้องยอมรับ

1. บอทจ๋า **ไม่ทวงเงินเอง** ต้องมีคนพิมพ์ `บอทจ๋า ใครยังไม่จ่าย`
2. บอทจ๋า **เชื่อคำพูดของคนจ่าย** ไม่รู้ว่าเงินเข้าจริงไหม บิลคือกระดานจด ไม่ใช่ระบบชำระเงิน

ทั้งสองข้อคือราคาที่จ่ายเพื่ออยู่ใน free tier ต้องเขียนบอกผู้ใช้ตรง ๆ ไม่ใช่แอบเงียบ

# 5. กติกาการคิดเงิน

## 5.1 หน่วยเงิน

เก็บเป็น **สตางค์ (integer)** ทั้งหมด ห้ามใช้ float กับเงิน

```text
ค่าคอร์ท 600 บาท → 60000
```

## 5.2 การหาร

```text
ยอดรวม = ผลรวมของทุกรายการ
คนละ   = ยอดรวม ÷ จำนวนคนที่ลงชื่อรอบนั้น
```

ทุกรายการหารเท่ากันหมด ไม่มีข้อยกเว้น

## 5.3 เศษสตางค์

หารไม่ลงตัว → **เศษตกที่ผู้สร้างรอบตี** (คนที่คิดเงินและรับโอน) เสมอ

```text
760.00 ÷ 7 = 108.571... → คนอื่นคนละ 108.57, ผู้สร้างรอบจ่าย 108.58
```

เหตุผล: อธิบายได้ในประโยคเดียว และคนรับเงินเป็นคนรับเศษเอง

## 5.4 บิลผูกกับรอบไหน

**บิลทำกับรอบ `open` ของกลุ่มเท่านั้น** ไม่มีรอบ open → `NO_OPEN_GAME` (error code เดิม ไม่ต้องเพิ่มใหม่)

เพราะลำดับการใช้งานจริงคือคิดเงินก่อนปิดรอบเสมอ (ดู §7) การไปไล่หารอบ `completed` ย้อนหลัง
จึงเป็นทางที่ไม่มีใครเดิน แต่ทำให้ต้องเขียน branch เพิ่มและทดสอบเพิ่ม

ส่วนการ **อ่านบิล / กดจ่าย / ถามว่าใครยังไม่จ่าย** ทำกับ **บิลล่าสุดของกลุ่มที่ยัง `sent`**
ไม่ผูกกับสถานะของรอบ เพราะรอบปิดไปแล้วก็ยังตามเก็บเงินกันต่อได้

ถ้าคิดเงินรอบใหม่ทั้งที่บิลเก่ายังค้าง การ์ดยืนยันจะขึ้นบรรทัดเตือนว่า
`⚠️ บิลรอบก่อนยังค้างอยู่ N คน` ให้เห็นก่อนกด ไม่ใช่ปล่อยให้บิลเก่าหายเงียบ

## 5.5 ใครคือผู้ร่วมจ่าย

**Snapshot ตอนกดยืนยันสร้างบิล** จาก `game_players` ที่ `status = 'joined'`

- ถอนชื่อหลังบิลออกแล้ว → ยังต้องจ่าย (มาตีแล้ว)
- ลงชื่อหลังบิลออกแล้ว → ไม่อยู่ในบิลนี้
- สร้างบิลตอนไม่มีใครลงชื่อ → `NO_PLAYERS_TO_SPLIT`

## 5.6 สถานะการจ่าย

```text
unpaid → paid
```

มีสองสถานะเท่านั้น ไม่มีขั้นรอยืนยัน

- คนที่อยู่ในบิลบอกว่าจ่ายแล้ว → `paid` ทันที
- กดผิด → พิมพ์ `บอทจ๋า ยังไม่จ่าย` กลับเป็น `unpaid` ได้เอง
- **"จ่ายครบแล้ว" คำนวณสด** จาก `bill_shares` ไม่เก็บเป็น status เพื่อไม่ให้ข้อมูลสองที่ขัดกันเอง

## 5.7 ปิดรอบตอนยังจ่ายไม่ครบ

**ปิดรอบได้เสมอ บอทไม่ขวาง** แต่ต้องบอกให้ผู้สร้างรอบรู้ก่อนและหลังกด

```text
ไม่มีบิล           → ปิดรอบตามปกติ (ก๊วนที่ไม่ใช้ฟีเจอร์คิดเงิน)
มีบิล จ่ายครบ      → ปิดรอบตามปกติ
มีบิล ยังมีคนค้าง  → การ์ดยืนยันขึ้นรายชื่อคนค้าง แล้วปิดได้
                     ข้อความหลังปิดรอบย้ำอีกครั้งว่าเหลือใคร ค้างเท่าไหร่
```

การ์ดยืนยันปิดรอบ:

```text
🔒 ปิดรอบ พุธ 16 ก.ย.?

⚠️ ยังมีคนไม่จ่าย 3 คน
ชูใจ, วีระ, อารีย์ — รวม 285.00

ปิดรอบแล้วยังกด "จ่ายแล้ว" และถาม "ใครยังไม่จ่าย" ได้ตามปกติ

[ ✅ ปิดรอบ ] [ ❌ ไม่ปิด ]
```

เหตุผลที่ไม่บล็อก: ถ้าห้ามปิด กลุ่มจะติดอยู่กับรอบที่ปิดไม่ได้ และ**เปิดรอบใหม่ไม่ได้ด้วย**
เพราะ spec §7 กำหนดว่ากลุ่มหนึ่งมีรอบ `open` ได้รอบเดียว — คนหนึ่งคนที่ไม่จ่ายจะทำให้ทั้งก๊วนใช้บอทไม่ได้

**บิลไม่หายไปพร้อมรอบ** ยังกด `จ่ายแล้ว` และถาม `ใครยังไม่จ่าย` ได้ต่อจนกว่าจะครบ
ใช้กฎเดียวกันกับ `ยกเลิก` รอบตี

# 6. เลขพร้อมเพย์ = ข้อมูลของรอบตี

เก็บที่ `games.promptpay` ปฏิบัติเหมือน `location_url` ทุกประการ — เป็นช่อง **optional ที่ถามครั้งเดียวและข้ามได้**

| จุด | ทำยังไง (ของเดิมที่ copy ได้เลย) |
| --- | --- |
| ตอนเปิดรอบ | `advanceCreateWizard` ใน `src/router/wizard.ts` มี pattern `location_asked` อยู่แล้ว เพิ่ม `promptpay_asked` แบบเดียวกัน |
| ตอนพิมพ์ตอบ | `handleTextAnswer` ใน `src/router/text-answer.ts` เพิ่มเคส `awaiting === "promptpay"` |
| ตอนแก้ไขรอบ | เพิ่ม 1 บรรทัดใน `EDIT_FIELD_QUESTIONS` ของ `src/router/postback.ts` |
| ตอน LLM | เพิ่ม param `promptpay?` ใน `propose_create_game` / `propose_edit_game` |
| ปุ่ม `ใช้อันเดิม` | ดึงเลขล่าสุดของกลุ่มจากรอบก่อนหน้า ไม่ต้องพิมพ์ซ้ำทุกสัปดาห์ |

Validation:

```text
ตัดอักขระที่ไม่ใช่ตัวเลขออกก่อนเก็บ
เหลือ 10 หลัก (เบอร์มือถือ) หรือ 13 หลัก (เลขบัตรประชาชน)
อื่น ๆ → PROMPTPAY_INVALID
```

แสดงผลคืนเป็นรูปแบบอ่านง่าย (`081-234-5678`) และโชว์เฉพาะในการ์ดบิล ไม่โชว์ในการ์ดรอบตีปกติ

> เก็บเป็นข้อความที่ผู้ใช้พิมพ์เอง ไม่ตรวจกับธนาคาร ไม่ผูกบัญชี ไม่แตะเงินจริง

# 7. Flow ทั้งรอบ

```text
เปิดตี (ใส่เลขพร้อมเพย์)
   ↓
ลงชื่อกันในกลุ่ม
   ↓
เล่นเสร็จ
   ↓
ผู้สร้างรอบพิมพ์ "บอทจ๋า คิดเงิน"  → ใส่ค่าคอร์ท / ลูกแบด / ค่าอื่น → ยืนยัน
   ↓
บอทส่งการ์ดบิล  → แต่ละคนกด 💸 จ่ายแล้ว
   ↓
ผู้สร้างรอบพิมพ์ "บอทจ๋า ปิดรอบ"
   ├─ จ่ายครบ    → ปิดรอบ เปิดรอบใหม่ได้
   └─ ยังมีคนค้าง → บอกว่าเหลือใครบ้าง แล้วปิดได้ (ตามเก็บต่อได้หลังปิดรอบ)
```

**คนที่คิดเงินคือผู้สร้างรอบตี** คนเดียวกับที่แก้ไข / ยกเลิก / ปิดรอบได้ (spec §21)
ใช้ `NOT_GAME_CREATOR` ตัวเดิม ไม่ต้องมีแนวคิด "ผู้สร้างบิล" แยกอีกชั้น

## 7.1 Wizard คิดเงิน

ใช้ `pending_actions` และ postback action `wizard` / `confirm` / `reject` **ของเดิมทั้งหมด**
เพิ่มแค่ `action_type = 'create_bill' | 'cancel_bill'` เท่านั้น (ดู §11)

```text

       ↓

       [ 300 ] [ 400 ] [ 500 ] [ พิมพ์เอง ]
       ↓

       [ 1 ] [ 2 ] [ 3 ] [ 4 ] [ ไม่มี ]
       ↓

       [ 20 ] [ 25 ] [ 30 ] [ พิมพ์เอง ]      ← ค่าล่าสุดของกลุ่มขึ้นเป็นตัวเลือกแรก
```

# 8. Research: ตรวจสลิปทำได้แค่ไหน (และทำไมถึงไม่ทำ)

## 8.1 รับรูปสลิป — ทำได้ ฟรี

LINE ส่ง webhook event เมื่อมีคนส่งรูป (`message.type = "image"` พร้อม `message.id`)
แล้วโหลดไฟล์จริงได้ที่ (คนละ host กับ API ปกติ):

```text
GET https://api-data.line.me/v2/bot/message/{messageId}/content
Authorization: Bearer {channel access token}
```

## 8.2 ตรวจว่าสลิปจริงหรือปลอม — ไม่ฟรี

| ทางเลือก | สภาพจริง |
| --- | --- |
| **EasySlip** | 9 แพ็กเกจ **99–40,000 บาท/เดือน** ถูกสุด 250 ครั้ง/เดือน มีให้ทดลองฟรี ไม่มีแพ็กเกจฟรีถาวร |
| **SlipOK** | คิดเป็นแพ็กเกจรายเดือนเช่นกัน |
| **KBank Slip Verification API** | ต้องสมัคร developer portal + ทำ Two-Way SSL ออกแบบมาสำหรับร้านค้า |
| **อ่าน QR ในสลิปเอง** | QR เก็บแค่ **เลขอ้างอิงรายการ + ธนาคารต้นทาง** ไม่มียอดเงิน สุดท้ายต้องยิง API ธนาคารอยู่ดี |
| **ให้ Gemini อ่านรูป (OCR)** | ฟรีใน free tier อ่านยอด/เวลาได้ แต่ **พิสูจน์ของปลอมไม่ได้** เว็บสร้างสลิปปลอมทำภาพให้อ่านออกได้เหมือนกัน |

## 8.3 ข้อสรุป

**ไม่รับสลิป ไม่ตรวจสลิป ไม่เก็บรูป และไม่มีขั้นให้ผู้เก็บเงินกดยืนยัน**

เมื่อบอทพิสูจน์อะไรไม่ได้อยู่แล้ว การเพิ่มขั้นตอนเหล่านี้มีแต่ทำให้ UX ยาวขึ้นโดยไม่ได้ความมั่นใจเพิ่ม
ใครจะส่งสลิปเข้ากลุ่มก็ส่งได้ตามปกติ รูปอยู่ในแชทให้ทุกคนเลื่อนดูเอง

ถ้าวันหนึ่งอยากตรวจสลิปจริง ต้องยอมจ่ายอย่างน้อย 99 บาท/เดือน ซึ่งขัด Free-First ในตอนนี้

# 10. Commands และ Postback

## Rule-based (เพิ่มใน `RULE_COMMANDS`)

| คำสั่ง | ทำอะไร |
| --- | --- |
| `คิดเงิน` | เริ่ม wizard สร้างบิล |
| `บิล` / `ใครยังไม่จ่าย` | แสดงการ์ดบิล + ใครจ่ายแล้ว/ยังไม่จ่าย (alias กัน เหมือน `ใครตีบ้าง`/`รายชื่อ`) |
| `จ่ายแล้ว` | ตั้งสถานะตัวเองเป็น `paid` |
| `ยังไม่จ่าย` | ย้อนสถานะตัวเองกลับเป็น `unpaid` |
| `ยกเลิกบิล` | ขอยืนยันเพื่อยกเลิก (เฉพาะผู้สร้างรอบตี) |

## Postback Data

เพิ่ม step ใน action `wizard` ของเดิม:

```text
action=wizard&pending_id=<uuid>&step=court_fee|shuttle_count|shuttle_price|extra&value=<x>
```

เพิ่ม action ใหม่ 3 ตัว ที่**ไม่ต้องอ้าง id** (ยึดแบบเดียวกับ `join` / `leave` / `list` ที่ทำกับรอบ open ของกลุ่มนั้น):

```text
action=bill_paid
action=bill_unpaid
action=bill_status
```

`confirm` / `reject` ใช้ของเดิมทั้งหมด เพราะ `runConfirm` ใน `src/router/postback.ts` แยกงานตาม `pending.action_type` อยู่แล้ว

# 11. Database

## bills

```text
id             BIGSERIAL
game_id        BIGINT REFERENCES games(id)
created_by     BIGINT REFERENCES users(id)
status         TEXT  -- sent | cancelled
items          JSONB -- [{ label, quantity, unit_price_satang, amount_satang }]
total_satang   BIGINT
created_at
updated_at
```

```text
UNIQUE(game_id) WHERE status = 'sent'
```

**ทำไม `items` เป็น jsonb ไม่ใช่ตารางแยก:** รายการมี 1-5 แถว เขียนครั้งเดียวตอนสร้าง อ่านยกชุดเสมอ
ไม่เคย query ทีละรายการ และแก้ไม่ได้หลังส่ง → ตารางแยกให้แค่ join เพิ่มโดยไม่ได้อะไรกลับมา
(ถ้าวันหนึ่งจะทำสรุป "เดือนนี้จ่ายค่าลูกไปเท่าไหร่" ค่อยแตกเป็นตารางตอนนั้น)

**ไม่มี status `draft`** เพราะ wizard เก็บร่างไว้ใน `pending_actions` อยู่แล้ว แถวใน `bills` เกิดตอนกดยืนยันเท่านั้น
**ไม่มี status `settled`** เพราะคำนวณสดจาก `bill_shares` ได้ ไม่ต้องกลัวสองที่ไม่ตรงกัน

## bill_shares

```text
id             BIGSERIAL
bill_id        BIGINT REFERENCES bills(id) ON DELETE CASCADE
user_id        BIGINT REFERENCES users(id)
amount_satang  BIGINT
paid           BOOLEAN NOT NULL DEFAULT false
paid_at        TIMESTAMPTZ
```

```text
UNIQUE(bill_id, user_id)
```

**Invariant (ทดสอบใน test ไม่ใช่ CHECK constraint):** `SUM(bill_shares.amount_satang) = bills.total_satang`

## games (เพิ่มช่อง)


## Transaction

| งาน | ต้องการอะไร |
| --- | --- |
| สร้างบิล | **1 transaction** — insert `bills` + insert `bill_shares` ทุกแถว ต้องเข้าด้วยกันหรือไม่เข้าเลย |
| กด `จ่ายแล้ว` | **ไม่ต้อง lock** — `UPDATE bill_shares SET paid = true WHERE bill_id = $1 AND user_id = $2 AND paid = false` แถวเดียว idempotent อยู่แล้ว |

ไม่ต้องใช้ `SELECT ... FOR UPDATE` แบบ join game เพราะไม่มีการนับเพดานหรือแข่งกันแย่งที่

# 12. Error Codes ที่เพิ่ม

| Code | ข้อความ |
| --- | --- |
| `NO_BILL` | `❌ รอบนี้ยังไม่ได้คิดเงิน` |
| `BILL_ALREADY_EXISTS` | `⛔ รอบนี้มีบิลอยู่แล้ว ถ้าจะแก้ต้องยกเลิกบิลก่อน` |
| `NOT_IN_BILL` | `ℹ️ คุณไม่ได้อยู่ในบิลรอบนี้` |
| `NO_PLAYERS_TO_SPLIT` | `❌ ยังไม่มีใครลงชื่อ เลยหารไม่ได้` |
| `AMOUNT_INVALID` | `❌ จำนวนเงินต้องมากกว่า 0 และไม่เกิน 100,000 บาท` |
| `PROMPTPAY_INVALID` | `❌ เลขพร้อมเพย์ต้องเป็นเบอร์มือถือ 10 หลัก หรือเลขบัตรประชาชน 13 หลัก` |

ใช้ code เดิมซ้ำ ไม่ต้องสร้างใหม่: `NO_OPEN_GAME` (ไม่มีรอบให้คิดเงิน), `NOT_GAME_CREATOR` (ไม่ใช่คนเปิดรอบ)

กด `จ่ายแล้ว` ซ้ำไม่ใช่ error — ตอบยืนยันซ้ำไปเฉย ๆ (idempotent) จึงไม่มี `ALREADY_PAID`
